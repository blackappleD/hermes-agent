## 1. 增加全链路 Trace 日志

当前张力场链路已经基本成立，但缺少足够清晰的过程记录。建议先补全 trace，记录每一步输入输出：

```plain&#x20;text
raw_event
event_view
signal_set
life_state_before / after
tension_operations
tension_set_before / after
action_potential
self_prompt
open_intent
arbitration_result
```

目标是让每次张力扰动都能被回放、定位和调参。

***

## 2. 扩展张力类型

当前张力类型偏通用，建议增加更贴近共博元神的张力类型：

```plain&#x20;text
bo:exploration
bo:competition
yue:compliance
risk:uncertainty
evidence:insufficient
credit:reputation
collab:dependency
governance:review_need
evolution:rule_seed
```

这些类型一期先用规则触发，不需要复杂模型。

示例：

```plain&#x20;text
证据缺失 → evidence:insufficient
权限不明 → yue:compliance / risk:uncertainty
高价值任务出现 → bo:competition
同类问题反复出现 → evolution:rule_seed
需要第三方判断 → governance:review_need
```

目标是让张力场不只是风险评分，而能表达元神在“博”与“约”之间的真实行动压力。

***

## 3. 建议新增向量记忆层

当前方案中没有向量库，张力扰动主要依赖结构化规则和关键词启发式，因此存在一个问题：系统只能基于当前事件做判断，较难利用历史相似任务、失败案例、规则触发记录和沉淀经验。

建议新增一个向量记忆层，用来存储和检索：

```plain&#x20;text
相似事件
相似任务
相似失败案例
相似规则触发记录
相似验收结果
历史 residue
```

它的作用不是直接决定行动，而是为张力场提供“历史经验依据”。

例如：

```plain&#x20;text
当前事件：Coder 准备提交 PR，但缺少测试 evidence

向量记忆层检索到：
过去类似 PR 多次因缺少测试 evidence 被 Tech Lead 拒绝

系统生成候选扰动：
evidence:insufficient 上升
risk:uncertainty 上升
yue:compliance 上升

最终由 TensionInterpreter 和 BoYueArbiter 决定是否采纳
```

也就是说，向量记忆层只提供经验信号，不绕过现有规则链路。

***

## 4. 增加失真保护机制

事件经过多层结构化处理后，可能出现信息压缩或误判。建议增加 `DistortionGuard`，重点检查：

```plain&#x20;text
原始事件包含 deploy / delete / token / publish / command，但 risk signal 没有上升
原始事件只是询问，但 OpenIntent 变成 use_tool
authorization unknown，但 recommended_depth 超过 report
evidence 缺失，但系统建议进入执行或验收
LLM 生成的 OpenIntent 偏离原始事件和 self_prompt
```

处理方式：

```plain&#x20;text
打 distortion_warning
提高 risk_cost
将推荐深度降级为 report / sandbox
必要时交给 BoYueArbiter 拦截
```

目标不是保证完全不失真，而是避免失真直接穿透到执行层。

***

## 5. 建立事件回放测试集

建议补一组 replay 测试事件，用来验证张力场是否稳定工作。

覆盖场景：

```plain&#x20;text
普通闲聊
公开需求
任务承接
代码执行
文件写入
外部消息
权限不明
审批/凭证
PR 合并
证据缺失
验收失败
用户打断
治理争议
规则冲突
```

每条事件标注期望输出：

```plain&#x20;text
expected_signals
expected_tension_types
expected_life_delta_range
expected_risk_range
expected_recommended_depth
must_not_action
```

验收重点：

```plain&#x20;text
高风险事件不能被判成低风险
权限不明不能直接进入 tool / world_publish
证据缺失必须触发 evidence:insufficient
公开需求必须触发 goal / opportunity 类张力
普通闲聊不能误触发执行动作
```

***

## 技术侧结论

当前结构化 Runtime 不需要推翻，下一步建议做五件事：

```plain&#x20;text
1. 补全 trace 日志，让张力扰动可回放
2. 扩展共博张力类型，让张力场更符合元神架构
3. 新增向量记忆层，让历史经验参与张力扰动
4. 增加 DistortionGuard，防止事件解释失真
5. 建立 replay 测试集，用标准事件验证效果
```
