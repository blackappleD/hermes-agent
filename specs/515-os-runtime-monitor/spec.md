# 功能规范: OS_RUNTIME 日志监控视图

**功能分支**: `515-os-runtime-monitor`
**创建时间**: 2026-05-14
**状态**: 草稿
**输入**: 用户描述: "在 dashboard 中增加一个专门针对 os_runtime 日志监控的页面，让我可以很方便地看到张力场、动力势能、生命状态等系统各自的具体参数的实时变化；保证页面风格一致；通过日志页面右上角自动刷新开关左边增加一个 OS_RUNTIME 开关，切换普通日志观察和 OS_RUNTIME 专属日志观察页面；OS_RUNTIME 日志要分模块展示其具体参数；页面底部可以展开 raw line 日志滚动。"

## 背景

Hermes dashboard 已有日志观察页面，用户可以查看普通日志、按文件/级别/组件筛选，并通过刷新与自动刷新观察运行状态。OS_RUNTIME 已逐步引入生命状态、张力场、行动势能、SelfPrompt、OpenIntent、裁判与 autonomous loop 等运行链路；普通日志行虽然包含这些信息，但用户需要在大量原始文本中搜索，难以及时判断每个系统的参数变化、趋势和最新状态。

本功能为现有日志页面增加 OS_RUNTIME 专属观察模式，使用户可以在同一个 dashboard 风格与入口中切换普通日志观察和 OS_RUNTIME 模块化监控。

## 目标

- 在日志页面右上角、自动刷新开关左侧提供 `OS_RUNTIME` 开关，用于切换普通日志观察和 OS_RUNTIME 专属观察。
- 在 OS_RUNTIME 观察模式中，按模块展示张力场、行动势能、生命状态等系统的最新参数、变化方向、更新时间和可读摘要。
- 保留底部可展开的 raw line 日志区域，便于用户核对模块化参数背后的原始日志。
- 保持现有 dashboard 的视觉语言、信息密度、控制样式和日志页工作习惯一致。

## 非目标

- 不改变 OS_RUNTIME 的决策逻辑、状态计算、日志写入语义或运行时安全边界。
- 不替代现有普通日志页面；开关关闭时普通日志观察必须保持原有体验。
- 不要求首版提供告警、持久化图表、跨会话统计报表或主动通知。
- 不在本功能中新增 OS_RUNTIME 配置、命令或后台循环能力。

## 用户场景与测试 *(必填)*

### 用户故事 1 - 从日志页切换到 OS_RUNTIME 观察 (优先级: P1)

作为正在调试 Hermes runtime 的用户，我希望在现有日志页面右上角直接打开 `OS_RUNTIME` 观察模式，从而不离开当前页面就能从普通日志切换到专属状态面板。

**优先级原因**: 这是功能入口；没有清晰的切换控件，用户无法发现或稳定访问专属监控视图。

**独立测试**: 打开 dashboard 日志页面，确认 `OS_RUNTIME` 开关位于自动刷新开关左侧；打开后显示 OS_RUNTIME 专属内容，关闭后恢复普通日志列表与原有筛选体验。

**验收场景**:

1. **给定** 用户位于普通日志页面，**当** 打开 `OS_RUNTIME` 开关，**那么** 页面主体切换为 OS_RUNTIME 专属观察视图，并保留日志页原有顶部控制风格。
2. **给定** 用户正在 OS_RUNTIME 观察模式，**当** 关闭 `OS_RUNTIME` 开关，**那么** 页面回到普通日志观察，已有日志筛选、刷新和滚动行为不被破坏。
3. **给定** 用户开启或关闭自动刷新，**当** `OS_RUNTIME` 开关状态变化，**那么** 自动刷新状态保持用户当前选择，不被切换操作重置。

---

### 用户故事 2 - 按模块查看 OS_RUNTIME 参数变化 (优先级: P1)

作为观察自治运行状态的用户，我希望张力场、行动势能、生命状态等系统分模块展示，使我能快速看到每个系统当前参数、最近变化和更新时间。

**优先级原因**: 用户提出的核心价值是“很方便地看到这几个系统各自具体参数的实时变化”；模块化参数是本功能的主体。

**独立测试**: 使用包含生命状态、张力场和行动势能日志的样例，打开 OS_RUNTIME 模式后，确认每个模块显示可读标题、最新更新时间、参数名、当前值和变化提示。

**验收场景**:

1. **给定** 日志中存在生命状态更新，**当** 用户查看 OS_RUNTIME 模式，**那么** 生命状态模块展示 energy、fatigue、wakefulness、curiosity、restraint 或日志中等价字段的最新值与变化。
2. **给定** 日志中存在张力场更新，**当** 用户查看 OS_RUNTIME 模式，**那么** 张力场模块展示 active tensions、intensity、activation、trend、confidence 或日志中等价字段的最新值与变化。
3. **给定** 日志中存在行动势能更新，**当** 用户查看 OS_RUNTIME 模式，**那么** 行动势能模块展示 value potential、learning potential、risk cost、overall score、recommended depth 或日志中等价字段的最新值与变化。
4. **给定** 日志中存在 SelfPrompt、OpenIntent、Arbitration 或 Autonomous Loop 摘要，**当** 用户查看 OS_RUNTIME 模式，**那么** 页面以附加模块展示这些信息，且不会挤占 P1 模块的可读性。

---

### 用户故事 3 - 展开底部 raw line 日志核对细节 (优先级: P2)

作为排查问题的用户，我希望在模块化参数下方展开原始 OS_RUNTIME 日志行，以便验证参数来自哪些日志并查看未被结构化展示的细节。

**优先级原因**: 原始日志是模块化视图的证据来源，也能覆盖无法解析或暂未建模的新日志字段。

**独立测试**: 在 OS_RUNTIME 模式底部展开 raw line 区域，确认该区域独立滚动、只展示 OS_RUNTIME 相关原始行，并可折叠回模块视图。

**验收场景**:

1. **给定** OS_RUNTIME 模块视图已显示，**当** 用户展开底部 raw line 区域，**那么** 页面底部出现可滚动的原始日志行列表，模块视图保持可见或可恢复。
2. **给定** raw line 区域已展开且日志持续刷新，**当** 新的 OS_RUNTIME 日志到达，**那么** raw line 列表按当前刷新节奏更新，并保留用户可阅读的滚动体验。
3. **给定** 某些 OS_RUNTIME 日志无法解析成模块参数，**当** 用户查看 raw line 区域，**那么** 这些日志仍可在原始行中被看到。

---

### 用户故事 4 - 空状态与异常日志可理解 (优先级: P3)

作为用户，我希望当没有 OS_RUNTIME 日志或日志格式不完整时，页面仍能给出清楚状态，而不是显示空白或误导性参数。

**优先级原因**: OS_RUNTIME 可能未启用、刚启动或只输出部分模块日志；清晰空状态能避免错误判断。

**独立测试**: 使用无 OS_RUNTIME 日志、只有部分模块日志、以及包含格式异常日志的样例，确认页面显示缺失提示、局部模块和 raw line 证据。

**验收场景**:

1. **给定** 当前日志中没有 OS_RUNTIME 相关内容，**当** 用户打开 OS_RUNTIME 模式，**那么** 页面显示明确空状态，并提供继续刷新或返回普通日志观察的路径。
2. **给定** 当前只存在部分模块日志，**当** 用户打开 OS_RUNTIME 模式，**那么** 已有模块正常展示，缺失模块显示“暂无数据”或等价状态。
3. **给定** 日志行包含不完整或无法识别的参数，**当** 页面刷新，**那么** 已识别参数继续展示，无法识别内容进入 raw line，不导致整个视图失败。

### 边界情况

- 当 `OS_RUNTIME` 开关关闭时，普通日志页面的文件、级别、组件、行数、刷新和滚动行为必须保持原有语义。
- 当自动刷新开启且用户处于 OS_RUNTIME 模式时，模块参数按同一刷新节奏更新，不额外制造独立刷新状态。
- 当日志量很大时，模块区域优先展示最新快照，raw line 区域以可滚动方式承载更多历史行。
- 当某个参数在最新刷新中没有新值时，页面保留最近已知值并标明更新时间，避免把缺失误读为零值。
- 当日志中出现同一模块多个连续更新时，页面展示最新值，并让变化提示反映相邻两次可比较快照。
- 当用户在 raw line 区域滚动查看历史日志时，刷新不应强行破坏阅读位置，除非用户主动回到底部或执行手动刷新。

## 需求 *(必填)*

### 功能需求

- **FR-001**: 日志页面必须在右上角自动刷新开关左侧提供 `OS_RUNTIME` 开关，用于进入或退出 OS_RUNTIME 专属观察模式。
- **FR-002**: `OS_RUNTIME` 开关关闭时，普通日志观察页面必须保持现有筛选、刷新、滚动和显示行为。
- **FR-003**: `OS_RUNTIME` 开关打开时，页面主体必须显示 OS_RUNTIME 专属观察视图，而不是普通日志文本列表。
- **FR-004**: OS_RUNTIME 观察视图必须至少包含生命状态、张力场和行动势能三个模块区域。
- **FR-005**: 每个模块区域必须展示模块名称、最新更新时间、当前状态摘要、参数名、当前值和最近变化提示。
- **FR-006**: 生命状态模块必须优先展示 energy、fatigue、wakefulness、curiosity、restraint 等生命状态相关参数；当日志使用等价字段名时，页面必须以用户可理解的名称呈现。
- **FR-007**: 张力场模块必须优先展示 active tensions、intensity、activation、trend、confidence 等张力相关参数；当日志只提供摘要时，页面必须展示可用摘要并标明缺失参数。
- **FR-008**: 行动势能模块必须优先展示 value potential、learning potential、risk cost、overall score、recommended depth 等行动决策相关参数；当日志只提供部分评分时，页面必须展示已知字段。
- **FR-009**: 当日志中存在 SelfPrompt、OpenIntent、Arbitration、Autonomous Loop 或 Runtime Driver 摘要时，OS_RUNTIME 视图必须能以附加模块或摘要区展示这些信息。
- **FR-010**: 模块参数必须随手动刷新和自动刷新更新，并让用户能分辨值是否变化、何时变化。
- **FR-011**: OS_RUNTIME 视图必须提供底部可展开的 raw line 区域，用于显示 OS_RUNTIME 相关原始日志行。
- **FR-012**: raw line 区域必须支持独立滚动，并能在展开和折叠之间切换。
- **FR-013**: 无法解析为模块参数的 OS_RUNTIME 日志必须仍出现在 raw line 区域中，不得静默丢失。
- **FR-014**: 当没有 OS_RUNTIME 日志时，页面必须显示清楚的空状态，而不是空白模块或误导性零值。
- **FR-015**: 页面视觉风格、控件密度、字体层级、边框、色彩和交互反馈必须与现有 dashboard 日志页面保持一致。
- **FR-016**: 模块视图必须避免参数文字、数值、徽标和 raw line 区域在常见桌面宽度下互相遮挡。

### 关键实体

- **OSRuntimeObservationMode**: 日志页面中的专属观察模式，表示当前页面是在普通日志观察还是 OS_RUNTIME 模块化观察。
- **RuntimeModuleSnapshot**: 某个 OS_RUNTIME 模块的最新可读状态，包含模块名称、更新时间、摘要、参数集合和变化提示。
- **RuntimeParameterReading**: 单个参数的当前值、显示名称、上一次可比较值、变化方向和证据来源。
- **RuntimeRawLine**: 被识别为 OS_RUNTIME 相关的原始日志行，可作为模块参数的证据或未解析信息的保底展示。
- **RuntimeEmptyState**: 没有 OS_RUNTIME 数据或某个模块暂缺数据时展示给用户的状态说明。

## 成功标准 *(必填)*

### 可衡量的结果

- **SC-001**: 用户可以在日志页面通过一次开关操作进入 OS_RUNTIME 观察模式，并通过一次开关操作返回普通日志观察。
- **SC-002**: 对包含生命状态、张力场和行动势能更新的日志样例，用户能在 30 秒内找到这三个模块的当前值和最近变化。
- **SC-003**: 在自动刷新开启时，新出现的 OS_RUNTIME 参数变化会在下一次刷新完成后反映在对应模块中。
- **SC-004**: 对至少 200 行 OS_RUNTIME 原始日志，底部 raw line 区域可展开、折叠并独立滚动，且不遮挡顶部控制区。
- **SC-005**: 当没有 OS_RUNTIME 日志时，页面显示明确空状态，用户不会看到被误认为真实数据的默认零值。
- **SC-006**: 普通日志观察的核心流程在 `OS_RUNTIME` 开关关闭时保持可用，包括选择日志文件、筛选级别、筛选组件、选择行数、刷新和自动刷新。

## 假设

- OS_RUNTIME 相关日志会在日志行中包含可识别的 os_runtime、runtime driver、life state、tension field、action potential、self prompt、intent、arbitration 或 autonomous loop 等标识之一。
- 首版“实时变化”复用日志页现有手动刷新与自动刷新节奏；不要求新增独立流式通道。
- 专属观察模式是日志页面内的视图切换，不是 dashboard 侧边栏中的新主导航项。
- 用户主要在桌面 dashboard 中使用该能力；移动端只需保持基本可读和不遮挡。
- OS_RUNTIME 日志格式可能逐步演进，因此模块化展示必须优先呈现已识别字段，并以 raw line 覆盖未知字段。
