# 功能规范: World Event Dashboard

**功能分支**: `516-world-event-dashboard`
**创建时间**: 2026-05-15
**状态**: 草稿
**输入**: 用户描述: "在 dashboard 中增加一个页面查看投影成的 Hermes MessageEvent，以及对应的消费到的 NATS event。注意保持风格统一"

## Clarifications

### Session 2026-05-15

- Q: v1 这个 dashboard 页面应该覆盖哪些事件来源? → A: 覆盖所有 gateway 入站事件, 只要它们最终可投影或尝试投影成 Hermes MessageEvent; 页面必须能通过分类筛选出 Linz World/NATS 事件。
- Q: 这个页面的数据刷新方式应该是哪一种? → A: 手动刷新 + 自动刷新开关, 复用 dashboard 现有刷新风格和节奏。
- Q: 详情页里的原始事件载荷应该怎么展示? → A: 默认摘要; 展开后显示完整原始 payload, 不需要脱敏, 因为 dashboard 只在用户电脑本地运行。
- Q: 事件列表默认应该展示/查询多大范围? → A: 默认最近 100 条, 支持筛选后分页/加载更多。
- Q: 这些入站事件与 MessageEvent 投影记录是否必须跨 gateway/dashboard 重启保留? → A: 必须本地持久化, 重启后仍可查看最近历史记录。

## 用户场景与测试 *(必填)*

### 用户故事 1 - 排查世界事件投影链路 (优先级: P1)

作为 Hermes 运维者或开发者, 我希望在 dashboard 中打开一个专门页面, 看到 gateway 消费到的入站事件如何被投影成 Hermes MessageEvent, 并能单独筛选 Linz World/NATS 事件, 以便快速判断事件是否被收到、是否被去重、是否进入会话处理, 以及投影结果是否符合预期。

**优先级原因**: 这是确认 Linz World 与 OS Runtime 长期监听链路是否可靠的最短路径; 没有这个视图时, 用户必须跨日志、状态页和本地存储手动拼接证据。

**独立测试**: 准备至少一条已消费且已投影的 gateway 入站事件记录, 打开新页面, 验证列表中能看到该事件, 并能进入详情查看原始入站事件与 Hermes MessageEvent 的一一对应关系; 再准备一条 Linz World/NATS 事件, 验证可通过分类筛选单独定位。

**验收场景**:

1. **给定** 系统已消费至少一条 gateway 入站事件且已生成 Hermes MessageEvent, **当** 用户打开事件投影视图, **那么** 页面展示该事件的时间、来源、事件类型、消费状态、投影状态和关联 MessageEvent 摘要。
2. **给定** 用户从列表选择一条事件, **当** 用户查看详情, **那么** 页面同时展示消费到的事件信息和投影后的 MessageEvent 信息, 并清晰标示它们的关联字段与处理状态。
3. **给定** 一条事件尚未成功投影或处理失败, **当** 用户查看列表或详情, **那么** 页面突出显示失败/待处理状态和可读的失败原因, 不要求用户阅读后台日志才能理解当前状态。
4. **给定** 页面包含多个来源类别的 gateway 入站事件, **当** 用户选择 Linz World/NATS 分类筛选, **那么** 列表只展示该分类下的事件并保留可进入详情的投影关系。
5. **给定** gateway 已消费并记录若干入站事件, **当** gateway 或 dashboard 重启后用户重新打开事件投影视图, **那么** 最近历史记录仍可查询, 且详情仍能展示原始事件与 MessageEvent 投影关系。

---

### 用户故事 2 - 筛选和定位问题事件 (优先级: P2)

作为排查人员, 我希望按状态、时间、来源分类、事件类型和搜索词筛选事件, 以便在大量 gateway 入站事件中定位某一次消费、某个平台/房间/关系/任务来源, 或某类投影异常。

**优先级原因**: 长期监听会产生连续事件流; 缺少筛选能力会让页面只适合演示, 不适合实际故障定位。

**独立测试**: 准备多条不同状态、来源分类和时间范围的记录, 调整筛选条件, 验证列表只展示匹配记录且清除筛选后恢复完整结果; 其中 Linz World/NATS 分类筛选必须可单独验证。

**验收场景**:

1. **给定** 页面存在 handled、processing、failed、duplicate 等不同状态的事件, **当** 用户按状态筛选, **那么** 列表只显示所选状态的记录并显示当前筛选条件。
2. **给定** 用户输入事件 ID、subject、event type、message ID 或来源关键字, **当** 用户执行搜索, **那么** 页面返回匹配记录并保留可进入详情的关联关系。
3. **给定** 当前筛选条件没有匹配记录, **当** 用户查看结果区, **那么** 页面显示空状态说明和清除筛选的明确操作。
4. **给定** 用户首次打开页面或清空筛选条件, **当** 页面加载默认列表, **那么** 页面展示最近 100 条事件记录, 并提供分页或加载更多入口继续查看更早记录。

---

### 用户故事 3 - 保持 dashboard 视觉与操作一致 (优先级: P3)

作为 dashboard 用户, 我希望新页面与现有 OS Runtime/日志类页面风格一致, 使用同样的导航、密度、色彩、状态标识和刷新行为, 以便不用学习一套新的界面语言。

**优先级原因**: 该页面面向高频排查场景, 风格不一致会降低可读性并破坏 dashboard 的整体体验。

**独立测试**: 在同一浏览器会话中切换现有 OS Runtime 页面和新事件投影视图, 验证导航位置、布局节奏、状态控件和刷新入口保持一致, 且在桌面宽屏与较窄视口下内容不重叠。

**验收场景**:

1. **给定** 用户位于 dashboard 任意页面, **当** 用户通过左侧导航进入事件投影视图, **那么** 新页面的入口、标题、控件密度和状态呈现与现有 dashboard 页面保持一致。
2. **给定** 用户在桌面和较窄视口查看页面, **当** 事件详情内容较长, **那么** 页面保持可读, 关键字段不互相遮挡, 长内容可被展开或滚动查看。
3. **给定** 用户打开事件投影视图, **当** 用户使用刷新按钮或自动刷新开关, **那么** 页面按现有 dashboard 风格更新数据, 并持续显示最近刷新时间、自动刷新状态和数据来源状态。

### 边界情况

- 当尚未消费任何 gateway 入站事件时, 页面显示清晰的空状态、当前监听配置状态和刷新操作, 不将空列表呈现为错误。
- 当 gateway 入站事件已持久化但 MessageEvent 尚未生成时, 页面显示为待投影/处理中, 并保留原事件详情。
- 当同一事件被重复消费或被去重时, 页面显示原始事件标识和去重结果, 避免误判为丢事件。
- 当事件载荷包含敏感字段或大体积内容时, 页面默认展示摘要和关键标识; 用户显式展开后可查看完整原始 payload, 且展开内容不得破坏布局。
- 当投影处理失败、监听器离线或授权状态异常时, 页面显示可读状态和最近错误摘要。
- 当事件字段缺失或格式不完整时, 页面仍能展示已知字段, 并用明确标签标出缺失信息。
- 当 gateway 或 dashboard 重启后, 页面不得只依赖当前进程内存状态; 已持久化的最近历史记录仍应可见。

## 需求 *(必填)*

### 功能需求

- **FR-001**: 系统必须在 dashboard 中提供一个独立页面, 用于查看所有可投影或已尝试投影成 Hermes MessageEvent 的 gateway 入站事件记录, 以及对应的 Hermes MessageEvent。
- **FR-002**: 系统必须在事件列表中展示每条记录的消费时间、事件标识、subject、event type、来源摘要、消费状态、投影状态和关联 MessageEvent 标识。
- **FR-003**: 用户必须能够选择任意列表记录并查看详情, 详情必须同时包含消费到的事件信息、投影后的 MessageEvent 信息、处理状态和最近错误摘要。
- **FR-004**: 系统必须清晰展示原始 gateway 入站事件与 Hermes MessageEvent 的关联关系, 包括能帮助用户确认同一事件链路的标识、时间、来源和状态字段; 对 Linz World/NATS 分类, 详情中必须保留对应 NATS subject 和事件标识。
- **FR-005**: 用户必须能够按时间范围、处理状态、来源分类、来源、subject、event type 和文本关键字筛选或搜索记录; 来源分类必须至少支持单独筛选 Linz World/NATS 事件。
- **FR-006**: 系统必须支持用户手动刷新数据并提供自动刷新开关, 自动刷新行为必须复用现有 dashboard 的风格和节奏; 页面必须显示最近一次刷新时间、自动刷新状态和数据来源状态。
- **FR-007**: 系统必须默认以摘要形式展示原始事件载荷, 并提供受控展开方式查看完整原始 payload; 由于 dashboard 仅在用户电脑本地运行, v1 不要求对展开后的原始 payload 做字段脱敏。
- **FR-008**: 系统必须对无记录、加载中、加载失败、监听离线、授权异常和投影失败等状态提供明确且一致的页面反馈。
- **FR-009**: 系统必须保持与现有 dashboard 视觉语言一致, 包括导航位置、暗色信息密度、状态标签、边框节奏、按钮样式和响应式行为。
- **FR-010**: 系统必须避免新页面影响现有 dashboard 页面和嵌入式聊天/终端体验; 当事件数据不可用时, 其他 dashboard 功能仍可正常使用。
- **FR-011**: 系统默认必须查询并展示最近 100 条事件记录; 当用户使用筛选、搜索或继续浏览更早记录时, 系统必须支持分页或加载更多, 并保持当前筛选条件。
- **FR-012**: 系统必须本地持久化 gateway 入站事件、投影状态和对应 Hermes MessageEvent 摘要/引用, 使 gateway 或 dashboard 重启后仍能查看最近历史记录; 页面不得依赖仅存在于当前进程内存中的 MessageEvent 对象。

### 关键实体 *(如果功能涉及数据则包含)*

- **Gateway 入站事件**: 从 gateway 各平台或事件源消费到、且可投影或已尝试投影成 Hermes MessageEvent 的原始事件记录; 关键属性包括事件标识、来源分类、subject、event type、来源、发生时间、消费时间、序列信息、载荷摘要、消费状态和错误摘要。Linz World/NATS 是必须可单独筛选的来源分类。
- **Hermes MessageEvent**: 由 gateway 入站事件投影成的 Hermes 会话消息; 关键属性包括消息标识、文本摘要、平台/通道来源、用户/参与者来源、原始事件引用和投影状态。
- **事件投影关联**: 连接 gateway 入站事件与 Hermes MessageEvent 的本地持久化排查记录; 关键属性包括关联标识、处理状态、去重结果、处理尝试次数、最近错误、审计引用、会话引用和 MessageEvent 摘要/引用。
- **页面筛选条件**: 用户当前用于定位记录的条件集合; 关键属性包括时间范围、状态集合、来源分类、来源、事件类型、搜索文本和分页/加载更多游标。

## 成功标准 *(必填)*

### 可衡量的结果

- **SC-001**: 用户可以在 2 分钟内从 dashboard 找到一条指定事件并确认其是否生成了 Hermes MessageEvent。
- **SC-002**: 用户可以在 3 次以内交互中从列表进入任一事件的关联详情。
- **SC-003**: 对 100 条最近事件记录, 用户在 5 秒内看到列表、筛选结果或明确的加载/错误状态。
- **SC-004**: 90% 的常见排查问题(是否收到、是否重复、是否投影、是否失败、失败原因是什么)可以仅通过该页面回答, 无需打开后台日志。
- **SC-005**: 在桌面宽屏和较窄视口下, 页面关键字段、筛选控件和详情内容均不发生不可读重叠。
- **SC-006**: 用户启用自动刷新后, 页面在现有 dashboard 刷新节奏内更新列表或明确显示数据来源不可用/刷新失败状态。
- **SC-007**: gateway 或 dashboard 重启后, 用户仍能在默认最近 100 条范围内看到重启前已持久化的事件投影记录, 并能进入详情查看关联信息。

## 假设

- 目标用户是已经能访问 Hermes dashboard 的本地用户、开发者或运维者。
- 页面使用现有 dashboard 的认证、导航和基础布局约定, 不新增独立登录流程。
- 页面刷新交互复用现有 dashboard 的刷新按钮、自动刷新开关和状态呈现约定。
- v1 范围聚焦查看、筛选、刷新和排查; 不包含在页面中重新投递、删除或修改事件。
- 事件数据来自 Hermes 本地持久化的 gateway 入站消费/投影记录; 页面必须能跨 gateway/dashboard 重启查询最近历史, 不依赖仅存在于运行中进程的临时状态。
- 默认列表范围是最近 100 条事件记录; 更早记录通过筛选、分页或加载更多访问。
- v1 覆盖所有可投影或已尝试投影成 Hermes MessageEvent 的 gateway 入站事件, 不限于 Linz World/NATS; Linz World/NATS 必须作为来源分类可被单独筛选。
- 为保护默认可读性和稳定布局, 原始载荷默认以摘要形式展示, 完整原始 payload 需要用户显式展开; v1 假设 dashboard 仅在用户电脑本地运行, 不要求对展开内容做脱敏处理。
